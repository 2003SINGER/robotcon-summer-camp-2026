## 补充核实：duanhuaxianghai 的 FreeRTOS 任务
- 3 个应用任务 + 1 个系统 idle（无软件定时器、无独立 CommTask/DebugTask）。
  - `MotorControlTask` "motor" 1ms/优先级5/栈512字 → `Mechanism_ControlTick`（app_tasks.c:29）
  - `SafetyTask` "safety" 10ms/优先级4/栈384字 → `Mechanism_Service`（掉线/超时/堵转→EStop + 遥测 + 栈高水位）（app_tasks.c:41）
  - `RobotFsmTask` "robot_fsm" 20ms/优先级3/栈384字 → `RobotFsm_Tick`（app_tasks.c:55）
  - idle 优先级0/栈192（vApplicationGetIdleTaskMemory）
- 配置：`configTICK_RATE_HZ=1000`（1kHz tick 驱动 delayUntil）；`configMAX_PRIORITIES=7`（用了3/4/5，留1/2/6）；`configUSE_PREEMPTION=1`；`configSUPPORT_STATIC_ALLOCATION=1 / DYNAMIC=0`（全静态，无堆碎片）；`configCHECK_FOR_STACK_OVERFLOW=2` + `vApplicationStackOverflowHook`→EStop(SCHEDULER)（app_tasks.c:99-106）；`configUSE_TIMERS=0`。
- 关键正确性：控制**不在中断**——TIM2 虽 CubeMX 配着(tim.c)但 main.c 没调 MX_TIM2_Init、也没 HAL_TIM_Base_Start_IT，**TIM2 实际没跑**，1kHz 全靠 FreeRTOS tick。FDCAN 中断优先级 0 最高(fdcan.c:114)但**不调任何 RTOS API**（只写快照/诊断），所以高于 configMAX_SYSCALL_INTERRUPT_PRIORITY(=5) 也安全——正是设计 §4 要的"ISR 只更新数据、不在 FreeRTOS 可调用范围"。
- 与设计 §4 对应：Motor/Safety/RobotFsm 三任务对上；CommTask(10ms)/DebugTask(100ms) 未独立建（遥测并入 SafetyTask 10ms）。bench 阶段可接受。
- 小瑕疵：TIM2 是 CubeMX 死代码可清；motor 栈512字(2KB)偏紧，靠 SafetyTask 高水位监控。（`configCPU_CLOCK_HZ=500000000` 现已与实际 500MHz 一致——main.c 已从 HSI/192 改为 HSE/500，与 README 对齐。）
