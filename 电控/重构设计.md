# 夏令营机构控制板重构设计（设计阶段）

> 状态：设计草案，尚未迁移或修改任何可运行工程。  
> 目标：把现有双 M2006、GM6020 的台架 Demo 合并为一块机构控制板上的可测试、可停机、可被主流程调用的软件。  
> 非目标：本阶段不重调 PID、不替换已验证的电机方向/ID、不控制底盘或气路板。

## 1. 已确认的边界

机构板负责：

- Z 轴升降：`M2006 × 1`，位置控制；具体反馈 ID 和机械零位待接线时确认。
- 前部斜向取料吸盘：`M2006 × 2`，两个电机同时输出以缩短两段式伸缩机构的总动作时间。两者不是两个需要强制同位的龙门轴；对每台电机保留独立的目标/行程参数，动作完成条件为两者均到位。
- 顶部翻转轴：`GM6020 × 1`，位置控制，当前台架工程使用反馈 `0x206` 与命令组 `0x1FF` 的第二路槽位。

其他控制板负责：

- 四麦轮底盘及 M3508。
- 真空泵、两只 3/2 阀、托片 5/2 阀及真空检测。

因此，机构板不应暗中假设自己能直接开泵、放真空或驱动底盘；完整赛题流程中的跨板动作必须经明确的命令/状态接口完成。

## 2. 现有工程的保留与处置

| 现有目录 | 角色 | 迁移原则 |
| --- | --- | --- |
| `xuke/M2006_Formal/` | 双 M2006 FDCAN 位置—速度串级 PID 台架工程 | 作为前伸机构的底层行为证据；保留 CAN ID、方向、编码器解析及已实测参数。 |
| `pengzixi/` | 与 Xuke 关键源码相同的源码副本 | 不再作为第二套维护入口；只保留来源，避免出现两份“当前代码”。 |
| `jiaojingwen/GM6020_2.0/` | GM6020 多圈角度/180°台架工程 | 保留 ID 映射、多圈累计和方向证据；移除上电自动翻转的流程。 |

新工程暂定名为 `机构控制器/`。旧工程均保持只读基线，任何迁移须能回到旧工程单独验证。

## 3. 总体架构

```text
FDCAN 接收中断
        │  仅解析反馈、更新时间戳；不做 PID、不等待
        ▼
Motor Registry（4 个电机的反馈快照）
        │
        ▼
MotorControlTask（1 kHz，唯一允许发送 DJI 电流帧）
        │  轴控制器：位置/速度 PID、限幅、故障输出为零
        ▼
ZAxis / Loader / Rotator
        │  对外只有目标、状态、故障
        ▼
MechanismTask（10 ms） ────► RobotFsmTask（20 ms） ────► 板间命令/状态
        │
        └── 限位、到位、超时、互锁
```

原则：

1. **只有一个 `main()`，只有一个电机控制循环。** 不合并三个旧 `while(1)`。
2. **CAN ISR 只更新数据。** 位置/速度 PID 在固定节拍任务中运行；不在中断或各机构私自发送 CAN。
3. **机构模块不知晓赛题流程。** 它们只接受目标并报告 `IDLE / MOVING / HOLDING / FAULT`。
4. **赛题流程不直接写电流、ID 或 `HAL_Delay()`。** 流程只调用机构命令、等待状态或超时。
5. **全部等待都有超时。** 禁止 `while (!done)` 与启动后自动执行 180°的隐式动作。

## 4. FreeRTOS 使用方式

本次引入 FreeRTOS，但不把每个电机拆成独立任务；四电机由同一高频任务统一调度，避免任务间抖动和 CAN 竞争。

| 任务 | 周期 / 优先级 | 责任 |
| --- | --- | --- |
| `MotorControlTask` | 1 ms / 最高 | 检查反馈新鲜度、运行 3×M2006 与 1×GM6020 控制器、打包发送 `0x200` / `0x1FF` 电流帧。 |
| `MechanismTask` | 10 ms / 中 | 执行 Z 轴、前伸、翻转的非阻塞子状态机；处理限位和到位判定。 |
| `RobotFsmTask` | 20 ms / 中低 | 执行跨机构和跨板动作流程，发请求并等外部板确认。 |
| `CommTask` | 10 ms / 中低 | 接收上位机/气路板/底盘板命令与状态，做协议校验和心跳。 |
| `DebugTask` | 100 ms / 最低 | 低频遥测、参数读取；不得在高频循环中阻塞串口。 |

CAN 回调不调用 FreeRTOS 队列 API：只写入每电机的反馈快照和接收时间。这样无需把 FDCAN 中断优先级调进 FreeRTOS 的可调用范围，控制任务在下一个 1 ms 周期读取快照即可。

## 5. 模块接口

### 5.1 底层电机与 CAN

```text
bsp/
  fdcan_bus.*             FDCAN 初始化、ISR 分发、两组电流帧打包
motor/
  dji_motor.*             反馈解析、多圈计数、掉线时间戳、方向/减速比
  pid.*                   带 dt、积分限幅与复位的 PID
  axis_controller.*       单轴位置—速度控制与电流限幅
```

`DjiMotor` 只保存反馈和配置；`AxisController` 才保存目标与 PID。所有 ID、方向、减速比、最大电流、限位极性放进 `board_config.h`，不得散落在 `main.c` 中。

初始 CAN 映射设计如下，带 `待确认` 的项必须通过上电前总线扫描和实际接线表锁定：

| 逻辑对象 | 反馈 ID | 命令组/槽位 | 状态 |
| --- | --- | --- | --- |
| 前伸 A（M2006） | `0x201` | `0x200` / 0 | 已在 Xuke 工程出现。 |
| 前伸 B（M2006） | `0x202` | `0x200` / 1 | 已在 Xuke 工程出现。 |
| Z 轴（M2006） | 建议预留 `0x203` | `0x200` / 2 | **待确认，不能直接写死。** |
| 翻转（GM6020） | `0x206` | `0x1FF` / 1 | 已在 `jiaojingwen/GM6020_2.0` 工程出现。 |

`0x200` 与 `0x1FF` 每个控制周期各发送一帧，未使用槽位写零。发送帧结构体必须清零初始化；FDCAN 过滤器先配置成功，再启动外设，并检查 HAL 返回值。

### 5.2 机构层

```text
mechanism/
  z_axis.*
  loader.*
  rotator.*
  mechanism_manager.*
```

统一接口：

```c
void Xxx_RequestPose(XxxPose pose);
void Xxx_RequestStop(void);
void Xxx_Update10ms(void);
XxxStatus Xxx_GetStatus(void);
bool Xxx_IsAtTarget(void);
FaultCode Xxx_GetFault(void);
```

- `ZAxis`：把毫米高度转换为编码器目标；机械零点与下/上限是必填配置；重力补偿接口预留但默认输出为 `0`，待实测后启用。
- `Loader`：对外暴露 `RETRACTED / PICK / STOWED` 等命名姿态；每个姿态保存 A、B 两套独立目标，不假设两台 M2006 的圈数相同。只有两电机均到位才报告完成。
- `Rotator`：暴露 `HOME / FLIPPED` 或绝对目标角；上电后保持当前位置，不允许自动转 180°。机械原点确认后才把逻辑 `0°` 绑定到实际角度。

## 6. 安全与故障模型

任何 `FAULT` 均应锁存，输出所有本板电机电流为零，直到接到显式清故障和重新回零命令。

| 触发条件 | 必需行为 |
| --- | --- |
| 某电机反馈超时 | 停止该命令组全部相关轴，报告 `MOTOR_OFFLINE`；不得拿旧反馈继续 PID。 |
| 软目标超出配置行程 | 拒绝命令，报告 `SOFT_LIMIT`。 |
| 物理限位被触发且仍朝该方向输出 | 立即归零电流，报告 `LIMIT_HIT`。 |
| 到位超时 / 电机堵转（大误差且低速） | 停止、锁存 `MOTION_TIMEOUT` 或 `STALL`。 |
| 急停 / 板间心跳丢失 | 全部本板输出零，并向气路板请求安全态。 |

机械尚未提供传感器清单，因此下列传感器是装车前的接口要求，而不是已确认存在：Z 轴上下限位、前伸收回/伸出限位、翻转原点或可靠机械基准。仅靠相对编码器圈数不能替代上电后的安全回零。

## 7. 主流程与板间协议

若机构板承担总流程，它必须把底盘和气路当作外部服务，而不是在机构模块中直接操作。

```text
RobotFsmTask
  REQUEST_LOADER_OUT
  → 等待 Loader = AT_TARGET
  → 请求气路板 FRONT_VACUUM_ON
  → 等待气路板 VACUUM_OK
  → REQUEST_LOADER_IN
  → 等待 Loader = AT_TARGET
  → 请求气路板 TRAY_EXTEND
  → 等待气路板 TRAY_AT_TARGET
```

协议先使用语义命令与状态，不传“电机转 N 圈”：

```text
命令：board, sequence, command, pose/value, timeout
状态：board, sequence, state, fault, heartbeat
```

物理通道（机构板 FDCAN2、CAN1 共线、UART 或其他）尚未确认，故本设计不预先占用某个 CAN ID；先确认控制板型号、可用收发器和三块板的接线后，再固化帧 ID 与仲裁优先级。

## 8. 迁移顺序与验收

1. **冻结与记录**：分别备份三份旧工程；记录每台电机的 ID、方向、物理职责、上电姿态、可用行程、已测 PID 和实际测试视频。
2. **建立空的新工程**：确认 STM32 型号、CubeMX 时钟、FDCAN 引脚及 FreeRTOS 时基；先只编译 FreeRTOS 空工程。
3. **迁移 CAN 与 Motor Registry**：先只观察 4 路反馈、打印 ID/频率/方向，不发送运动电流。
4. **迁移单轴闭环**：依次验证前伸 A、前伸 B、GM6020、Z 轴；每次只接一台执行器并保留可回退固件。
5. **封装三机构**：实现命名姿态、到位/超时/限位/故障；此阶段不接跨板赛题流程。
6. **接入板间协议与 Robot FSM**：先在仿真或空载下验证请求—确认—超时，再接真空与底盘。
7. **最后调参**：先机械回零、方向、限位和行程换算；再 P、D、重力补偿，最后才考虑 I。每次只改一轴、一组参数。

阶段验收标准：

- 任一机构在限位、断反馈、超时下均能在一个控制周期内停止本板输出。
- 1 kHz 电机任务没有阻塞串口、`HAL_Delay()` 或等待循环。
- 每个命名姿态都有实际单位（mm / deg）与编码器目标的对照表。
- 任何任务流程都可被暂停、超时退出，并能报告具体故障来源。
- 旧工程的单轴“能动”基线仍可独立复现；迁移后才允许归档，不删除。
